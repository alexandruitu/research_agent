# Slice 5 · Plan 2: Web backend + frontend for more sources — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Expose the 14-entry source registry (Plan 1) in the web app: sources API with key status, resolver
order in review settings, `text_licence` stored and shown, grouped Sources and Full-text settings, grouped source
picker in the field editor with per-source query preview.

**Architecture:** The registry (`research_agent.sources.REGISTRY`) is the single source of truth; web Literals
and lists are derived from `schemas.SEARCH_SOURCES` / `schemas.FULLTEXT_SOURCES`. The worker writes per-source key
status onto the `sources` row (never values). The frontend reads labels/groups/auth from `GET /sources`, with a
static fallback label map for rendering names in paper rows.

**Tech Stack:** FastAPI, SQLAlchemy/Alembic (PostgreSQL), pytest; React + TanStack Query, vitest.

## Decisions this plan takes

1. **Key status lives on the `sources` row** (new columns `key_present`, `key_accepted`, `key_detail`,
   `key_checked_at`), written by the worker at start-up. No new table: one row per source already exists.
2. **Seed:** migration 0006 inserts the 11 missing registry rows, all `enabled = false` (Europe PMC stays the
   only source enabled by default; existing rows keep their state).
3. **Key present** = every variable in `SourceInfo.env` is set (non-blank) for `auth == "required"`; for
   `optional`, the first variable. `auth == "none"` → `key_present = true`, detail "no key needed".
4. **Cheap validation at start-up:** only for sources with a present key and a `search` capability: one search
   for one result through the pipeline connector (`make_connector`, `limit=1`) with the worker's HTTP client.
   OK → accepted; any failure → `key_accepted = null`, detail "check failed" (the connector deliberately
   drops the HTTP cause when a key was sent, so a 401 cannot be told apart from an outage; we never guess
   "rejected"). `sciencedirect` (fulltext only) and
   `unpaywall` are not validated ("not checked").
5. **Enabling without a required key → 422 `key_missing`** "Set <ENV> in the worker environment first", where
   ENV is the first missing required variable, based on the last worker report (`key_present`). A source never
   reported by a worker counts as missing for `auth == "required"`.
6. **`source_check` job** works for every *search* source through `make_connector`; `unpaywall` and
   `sciencedirect` have no search: their Test returns 422 `not_searchable` (the UI hides Test for them).
   `SourceKeyMissing` is reported as its own message ("core: set CORE_API_KEY in the worker environment").
7. **Query overrides:** `QueryOverrideIO` accepts every search source (no comma for OpenAlex). Frontend
   `querybuild.ts` is extended line-for-line with the Python builders (TERM/NOT/WILDCARDS/PLAIN).
8. **Field sources:** `sources` lists allow up to 12 (`len(SEARCH_SOURCES)`).
9. **Full text:** `FulltextIO.sources` is `list[FulltextSource]` (9, any order, unique). The Settings UI keeps an
   ordered list of *all* resolvers: enabled ones first in their saved order, then the disabled ones; up/down
   buttons reorder; saving sends only the enabled ones, in order.
10. **text_licence:** pipeline `graph.score_node` copies `text_licence` into `state.review[pid]` (one-line
    change, older reports lack it → `null`); web `paper_reviews.text_licence String(24) null`, `text_source`
    widened to `String(24)`; `PanelOut.text_licence`, `PaperRow.text_licence`.
11. **Export guard:** CSV/BibTeX export already writes metadata only. Add an explicit `EXPORT_FIELDS` doc +
    a test that a `publisher_licensed` paper's panel quotes/sections never appear in any export format.
12. **Frontend labels:** `labels.ts` gets a static `SOURCE_LABEL` for all 14 names + `demo` (paper rows render
    without waiting for `/sources`); groups/covers/auth come from the API.
13. **Google Scholar:** a fixed note in Settings → Sources: not supported, no official API.
