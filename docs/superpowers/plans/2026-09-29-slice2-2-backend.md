# Slice 2, plan 2: web backend for fields and sources — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Versioned fields with inclusion/exclusion criteria, admin-managed sources and settings, per-criterion
screening data in the paper table and drawer, and worker jobs (criteria test, source check, start-up key
check) — all behind the existing API contracts, which only gain fields.

**Architecture:** One Alembic migration (`0002`) adds `field_versions`, `sources`, `app_settings`,
`worker_status` and new columns, and backfills every existing field into version 1 with its criteria as
`legacy`. A small service module (`web/fields.py`) owns versioning (save, archive, domain building, content
matching); routers stay thin. `POST /runs` builds the run's `domain.json` dict from the field's current
version + enabled sources + the contact email; the worker writes it next to the run and passes `--domain`.
The importer reads the report's `contract.domain` and links runs to versions. New job kinds reuse the
pipeline's own functions (`JevScreener.screen_criteria`, connectors, `deduplicate`).

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 16 (`pgserver` in tests), httpx
(MockTransport in tests), pytest, ruff; `openapi-typescript` for `web/src/api/schema.d.ts`.

**Spec:** `docs/superpowers/specs/2026-09-28-fields-and-sources-design.md` (Data model, API, Errors,
Testing → Backend, Plans → 2). Pipeline facts: `docs/superpowers/plans/2026-09-28-slice2-1-pipeline.md`.

## Decisions this plan takes (the spec left them open)

1. **Resume of field runs needs no pipeline change.** `research-agent --resume` reads the saved contract,
   which contains `domain`; the CLI refuses `--domain` together with `--resume`, so the worker passes only
   `--resume` when `manifest.json` exists. When a failed field run has no manifest yet, the worker starts it
   again with `--domain` from the request saved in `run.manifest["domain_request"]`.
2. **Where the worker writes the request:** `<run_dir>/domain.request.json` (the pipeline copies it byte for
   byte to `<run_dir>/domain.json`; the same path would make `shutil.copyfile` fail).
3. **Legacy fields keep today's runs.** A field whose current version has only `legacy` criteria (every field
   that existed before this slice) starts a positional-topic run exactly as today (so the current tests and
   the React Start form are unchanged); it needs Europe PMC enabled (422 otherwise). A field with inclusion or
   exclusion criteria starts a `--domain` run.
4. **Sources of a run** = the version's source names ∩ enabled sources, each with the `sources` row's
   `max_results`; OpenAlex gets `contact = app_settings.contact_email` (omitted when empty). No enabled source
   left → 422 `no_enabled_source` "None of this field's sources is enabled". Saving a version does not check
   whether its sources are enabled (an admin may disable one later; the run refuses then).
5. **Version numbers:** a new version is `max(version) + 1`; `fields.current_version` is the last version
   *saved by a user*. An importer-created version (`note = "imported"`) never becomes current.
   `base_version` is compared with `current_version`; mismatch → 409 `stale_version`
   "This field changed since you opened it (now vN)". Saving an archived field → 409 `archived`.
6. **`fields.name` and `fields.topic` mirror the current version** (kept for old queries and `RunOut.field_name`);
   `topic` loses its unique constraint.
7. **Criteria rows are per version** (`criteria.version` = the field version number, `field_version_id` set).
   Keys `i1…`, `e1…` are generated by position on every save. `question` holds the criterion text.
8. **Per-paper sources are stored on the screening** (`screenings.sources`, JSONB list), not on `papers`
   (papers are shared across runs; "found by" is a property of a run). Not in the spec's table: an addition.
9. **`criterion_scores.probability` becomes nullable**: field runs have LLM answers without a Jev probability
   (Jev off or no abstract). The existing `ScreenCell.criteria` (`{key: float}`) and drawer
   `ScreeningOut.criteria` keep listing only scores that have a probability, so their types do not change;
   the new per-criterion data arrives in new fields (`ScreenCell.cells`, `ScreeningOut.criteria_table`).
10. **Criteria test in demo mode** uses Demo papers and an offline stand-in for Jev (probabilities from a hash
    of criterion key and paper id, model version `demo-jev`), so the e2e server needs no fake HTTP. Live mode
    needs `TYPESAFE_API_KEY` in the worker (else the job fails with "TYPESAFE_API_KEY is not set in the worker").
    ≤ 20 papers: each enabled source is searched with `max_results = 20` on the topic, deduplicated, the first 20
    kept. The job never writes to the paper tables; scratch files live in a temporary folder that is deleted.
11. **Source check:** query `"deep learning"`, limit 1, always live; the job completes (`done`) with
    `result.ok` true or false and the `sources` row gets `last_check_*`. The worker accepts an injected
    `http_client` (tests and, later, the e2e server) used by connectors and the key check.
12. **Key check:** one row per role in `worker_status` (roles of `live_models()` plus `jev`). Provider from
    the model id prefix (`anthropic:` / `openai:`), key variable `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` /
    `TYPESAFE_API_KEY`. Validation call: `GET https://api.anthropic.com/v1/models?limit=1` and
    `GET https://api.openai.com/v1/models` (free, list only); 200 → accepted, 401/403 → rejected, anything else →
    `null` with detail "check failed". TypeSafe has no free validation call → `key_accepted = null`,
    detail "not checked". No model configured → row with `model = null`, detail "no model configured". The check
    runs once when `research-web worker` (not `--once`) or `dev --with-worker` starts (`Worker(key_check=True)`);
    tests never enable it except through a mocked client.
13. **Eval runs** keep importing as today (legacy); `CallIndex` maps the `screen_criteria` role so a field eval
    run's LLM calls are found. Linking eval runs to field versions is left for later.
14. **Job kinds** `criteria_test` and `source_check` reuse the `jobs` table; `GET /jobs/{id}` is unchanged
    (creator or admin). They count towards the per-user active-job cap.
